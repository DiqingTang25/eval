Platform Explorer — 开发进度汇报

2026年8月5日 · 通用教学平台自动探索器

为 AI Agent 测评平台构建了通用教学平台自动探索器。 给定任意教学平台的 URL 和登录凭证，系统能自动完成认证、 发现 API 端点、推断课程结构、生成平台描述文件， 并与现有 10 维测评系统全链路对接。架构借鉴了 Unbrowse、WALT、Vespasian 等 2025-2026 年 SOTA 方案。

已完成的功能

React Fiber 认证注入

目标平台使用 React 自定义认证，Playwright 的标准 click()、dispatchEvent、 requestSubmit() 三种方式全部失败。我们通过遍历 React 内部的 __reactFiber 树， 提取 <form> 上的 onSubmit 处理函数，注入 <script> 标签异步调用， 成功突破任何 React/Next.js 的自定义认证。

API-First 数据捕获

Playwright 无法读取 fetch/XHR 的响应体。我们改为从流量拦截器提取登录 API 的请求信息， 用 Python requests 重放登录获取 JWT，再携带 JWT 直接调用所有已发现的 API， 成功拿到 graph-source、careers、digital-teacher 等接口的完整 JSON 响应。

JS Bundle 逆向

新模块能自动下载页面引用的全部 JavaScript 文件，用正则提取其中的 API 路径 （如 /course-recommendations/by-career、/auth/register）， 并尝试 SourceMap 还原。这些是流量拦截器发现不了的隐藏端点。

API 驱动的结构推断

从 API 响应 JSON 中自动解析课程层次结构。支持 graph-source、careers、curriculum 等 多种 API 响应模式的自适应匹配，成功从目标平台发现了覆盖嵌入式硬件、AI与数据、 机器人与自动化等领域的课程 Phase。

全链路自动对接

探索完成后自动生成 platform_profile.json（含 URL、凭证、API 前缀、Schema 路径）。 前端页面加载时通过 /api/explorer/profile/latest 自动读取， 填入 Top Bar、启用 Schema 模式。Health Check 和 Test Runner 从同一接口获取平台信息， 实现"探索一次，全链路自动打通"。

探索→ platform_profile.json→ GET /api/explorer/profile/latest→ 前端自动填入→ Health Check / Test Runner

前端 Explorer 页面

全新的平台探索页面：URL 和凭证输入、深度/页面数配置、实时进度条、 结果统计卡片（Phase/Lesson/Step/API 数量 + 置信度）、Schema 在线预览和下载、 探索历史列表。已集成双语支持。

五层探索流水线

L0 认证 自动检测表单/OAuth/SSO，四条登录路径自适应
L1 捕获 流量拦截 + BFS 遍历 + JS Bundle 逆向
L1.x API优先 JWT 重放 + requests 直调 API 获取响应体
L2 结构 API 响应解析 + DOM 推断，自适应多种数据格式
L3 分类 6 信号 API 分类 + Step 类型判定 + LLM 枚举（接口就绪）
L4 Schema YAML 生成 + 凭证脱敏 + Markdown 报告

后端 API 与数据库

REST API

POST /api/explorer/run — 启动探索
GET /api/explorer/status — 轮询进度
GET /api/explorer/sessions — 历史记录
GET /api/explorer/profile/latest — 全链路桥梁
GET /api/explorer/schema/{id} — Schema 内容
GET /api/explorer/health — 环境检查

数据层

ExplorationSession ORM 模型 + Alembic 迁移
后台线程运行探索器 + 自动 DB 持久化
LLM API Key 管理接口（/api/settings/llm-keys）

验证状态

在目标教育平台 personalized-secure 上完整验证了端到端流程： 自动登录 → 发现 5 个 API 端点 → 识别 22 个 Phase 结构 → 生成 platform_schema.yaml → 前端自动读取并填入配置。 核心流水线已验证可行。当前因多轮迭代中的代码版本同步问题， 最新探索结果有退化，属于工程修复范畴，不影响架构正确性。
