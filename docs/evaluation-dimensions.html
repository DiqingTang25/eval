🤖 8 维度 AI 回答评估 · 1-5 分制

每个维度由 3 个独立 LLM Judge（温度 0.1 / 0.3 / 0.5）并行评分， 取 中位数 作为最终分数，计算 标准差 作为置信度指标。 方差 > 1.0 标记为「需人工复核」。

D1

评估 AI 回答中事实陈述是否准确，是否存在幻觉（编造信息）。 这是最核心的维度，权重最高（30%）。
分数标准
5完全准确，无任何事实性错误或幻觉

3部分准确，存在 1-2 处事实错误
2多处错误，不可靠
1严重错误，充满幻觉

⚙️ 独立算法指标模块

以下算法模块不依赖 LLM，提供可解释的量化评分，可与 LLM Judge 评分融合使用。 位于 src/metrics.py。

📐 EmbeddingSimilarity — 语义相似度

sentence-transformers · paraphrase-multilingual-MiniLM-L12-v2 · 约120MB

将问题和回答分别编码为向量，计算余弦相似度，映射到 1-5 分。 用途：辅助 relevancy 评分。

评分映射

相似度范围得分
< 0.31 分
0.3 ~ 0.452 分
0.45 ~ 0.63 分
0.6 ~ 0.754 分
> 0.95 分

score = 1 + 4 × (similarity - 0.3) / 0.6

融合方式：final_relevancy = (llm_score + emb_score) / 2

🏗️ StructureCoverage — 结构化覆盖

jieba 分词 · 关键词提取 · 覆盖率计算

从黄金答案中提取 Top-5 关键词，检查 Agent 回答中覆盖了多少。 用途：辅助 completeness 评分。

评分公式

Step 1: jieba 分词 → 去停用词 → 提取黄金答案 Top-5 关键词

Step 2: 提取 Agent 回答 Top-10 关键词

Step 3: coverage = matched / total_ref_keywords

Step 4: score = 1 + 4 × coverage

融合方式：final_completeness = (llm_score + struct_score) / 2

🛡️ BoundaryScore — 边界合规评分

知识库语义检索 · 阈值判定

基于知识库检索相关性分数，判断回答是否在课程范围内。 用途：独立评估 boundary_compliance。

判定逻辑

综合分范围判定
≥ 0.7完全在课程范围内（4-5分）
0.3 ~ 0.7部分在课程范围内（1-4分）
< 0.3超出课程范围（1分）

combined = 0.6 × max_kb_score + 0.4 × avg_kb_score

详细阶段说明

第一阶段：初始化

  • 加载 config/test_config.yaml
  • 初始化模块：QuestionGenerator, Evaluator, FollowupGenerator, Reporter, BoundaryDetector
  • 通过 AgentRegistry 解析目标 Agent（Vercel / Dify）

第二阶段：问题选择

  • 优先从 data/golden_qa_bank.json 加载黄金 QA
  • 执行分层多样本抽样，按 (phase, type, difficulty) 三元组最大化覆盖
  • 如黄金 QA 不足，回退到 LLM 按需生成（含对抗性问题）

第三阶段：Agent 交互（浏览器自动化）

  • 启动 Playwright Chromium → 导航到 URL → 登录 → 打开聊天面板
  • 最多 N 轮对话（max_turns: 3）：发送问题 → 等待文本稳定（抗打字动画）→ 记录响应
  • 如 Agent 表达结束意图（"还有其他问题吗？"）→ 提前结束
  • 否则通过 FollowupGenerator 生成后续问题继续
  • 将所有轮次拼接为完整对话文本

第四阶段：边界检测

  • 关键词匹配：对 5 个阶段约 80 个课程术语进行命中率统计
  • LLM 判定：三分类 — in_scope / partial_match / out_of_scope
  • 综合输出：结合关键词命中率 + LLM 判定

第五阶段：多 Judge 评分

  • 构建评分 Prompt（问题 + 黄金答案 + 对话上下文 + 对抗性标注）
  • 3 个并行 LLM Judge（温度 0.1 / 0.3 / 0.5）各自评估 8 维度
  • 取中位数 → 计算标准差 → 方差 > 1.0 标记为 needs_human_review
  • 可选：嵌入相似度 + 结构覆盖率融合
  • 如有对抗性测试类型，应用权重调整
  • 综合分 = (正确性 + 相关性 + 完整性 + 引导性) / 4

第六阶段：报告输出

  • JSON 报告：reports/report_{timestamp}.json
  • Markdown 报告：reports/report_{timestamp}.md
  • 包含：摘要统计、每维度平均分、分层文字解读、边界检测统计、完整对话记录、优缺点分析
  • 仪表盘通过 WebSocket 实时推送进度（~20 种事件类型）
